Restaurant Waitlist DDD
1/ Define the scope:
    - Party Size
    - Add info to Waitlist
    - Position & Wait time
    Host task:
    - Add/Remove/Update/Notify
    - Mark Status: Notified/ Arrived/ No-Show/ Canceled/ Seated
2/ Ubiquitous language (every position uses the same language)
    - PartySize: a number of people in a group
    - Party: a group of people
    - Status: Notified/ Arrived/ No-Show/ Canceled/ Seated/ Waitting
    - WaitlistEntry: party's record on Waitlist
    - PreferredSeating: Indoor/ Outdoor/ Patio
    - QuoteWaitTime: estimate wait time
    - Positon: position of party on the list
3/ Bounded Text - Spilt system into logical areas
    Waitlist Management:
        - Manage waiting parties, including: walk-in, online, phone
        - Estimate wait time
        - Update Queue Position
        - Track Status (Notified/ Arrived/ No-Show/ Canceled/ Seated)
    Seat & Table Management
        - Table layout
        - Capacites
        - Availability
        - Appropriate Table base on PreferredSeating
    Guest Communication:
        - Guest Notification & Confirmation
        - Queue Change
        - Recorded Response (Arrived/ No-Show/ Canceled)
4/ Entities and Value Object
        Value Object: 
            - PartySize
            - QuoteWaitTime
            - Contact info
        Entities:
            * Identity: entry_id
            * Field: 
                - location_id
                - party_size (PartySize)
                - contact_info(Contact_info)
                - status (enum)
                - position (int)
                - quote_wait (QuoteWaitTime)
                - preferred_seating(PreferredSeating)
                - nofified_at/notified_at/seated_at
        Aggregate: Waitlist
            * Root: Waitlist
            * Entities:
                - Add new party
                - Notidfied next party
                - Seat Party
                - Cancel/ Mark No-Show
5/ Respository - get and save Waitlist Aggregate
    Waitlist Respository: Provide method for add/notify/remove and storing user info

6/ Service
    - Add party to waitlist service
    - Notify when table ready

7/ Domain Events - Communication between Bounded Context
    - Party Added To Waitlist
    - Party Removed from waitlist
    - Party Notified
    - Party Seated
    - Party Marked No Show
